# 批次生成：重抽、驗收、選片保護與 GPT 生圖

## 1. 驗收契約與不中途詢問

- 以使用者最新明確標準為準，記在專案 README。預設旁白畫面人物安靜；若使用者明確接受「語音通過但主持人張口」，嘴部活動不再單獨構成淘汰理由，也不必為此重拍。這不代表所有後續專案自動放寬，更不能宣稱已驗證對嘴同步。
- 燒入字幕／偽字、嚴重變形、人物重複、裁頭、參考圖靜態複製等仍須檢查。允許張口不等於允許其他瑕疵。
- 若使用者要求完成前不問問題，授權範圍內自行續跑：生成 → 畫面與語音 QA → 合格固定選片／不合格換 take → 逐章剪接與字幕。更新進度而非反覆要求批准；這不授權安裝模型、付費、上傳肖像或中斷他人工作。
- 渲染成功只是產出檔案。CPU Whisper 去除標點空白後逐字相符，只代表 ASR 文字一致，不代表畫面、音色、時間戳或完整聽感已通過。相似度高不能掩蓋多字／漏字／重複字；可疑辨識以原音與有提示轉錄複核。

## 2. 重抽與策略選擇

| 狀況 | 下一步 |
| --- | --- |
| 隨機視覺瑕疵，工作流正常 | 保持 prompt，遞增 take 並換 seed，只重拍失敗段 |
| 多次重複同類瑕疵 | 留存證據、檢查矛盾與參考圖；選擇繼續抽卡、最小修詞、簡化道具或 GPT 場景參考，不整批盲目改寫 |
| 畫面合格、語音失敗 | 優先借同段其他 take 的正確音訊，用既有 dub/splice；仍驗證成片與字幕時間 |
| 語音合格、畫面失敗 | 保存正確音訊供後續修補；換 take／視覺策略，不把 ASR pass 當整段 pass |

- 同 prefix 會去重沿用 queue/history；prompt 改過也必須使用新 take。不要在同一指令放同段多 take，既有 `story.TAKES` 可能只保留最後一個。
- 同一 seed 若多段出現相同瑕疵，可換下一輪 seed。不要因一段失敗重拍所有已驗收片段。
- 雙 GPU 各跑不同段；重用已啟動服務。背景完成通知後繼續 QA，不反覆輪詢 shell，不取消其他人的工作。

## 3. 已觀察到的提示詞經驗

- 身體參考圖可能帶胸牌；「服裝完整保留」與「禁止任何字」會衝突。保留原圖，prompt 明確排除胸牌與標誌；不要擅自覆寫參考圖。
- 家庭樹圖卡、時間軸、表格與文件容易長出偽字。可改為少量無標記立體模型；檢查正文、共用規則與音景，避免一面禁止紙張，一面又要求 paper rustles。
- 明寫固定鏡位仍可能推近。看 contact sheet **及結尾原始幀**，不能用 prompt 的宣告代替畫面證據。保留完整頭部、道具在下半部、首尾同尺度只是降低風險，並非保證。
- 曾有移除紙張後仍燒入大型字樣的 take；不能把單次改善宣稱為已解決，也不能把所有失敗都歸因於 seed。

## 4. GPT 生圖 → H3：可選、尚未驗證的備援

此策略已列為可考慮選項，**不是已驗證成功的本機流程**。重抽或 prompt 調整無法穩定達標時，可以先製作場景參考圖再生成影片；不必每次失敗都生圖。

1. 先確認可用的 GPT 圖像生成工具與肖像處理權限；不要把 Dreamina 或其他模型輸出稱為 GPT 圖。沒有工具／權限就記錄不可用，繼續現有授權策略，不擅自安裝、付費或傳送肖像至外部服務。
2. 使用已授權的人物參考固定李醫師身分，生成直式 9:16 場景圖：完整頭部、清楚手部、少量無字道具、無胸牌／標誌／字幕，構圖與分鏡一致。原始臉部／全身參考保持不變。
3. 先驗收靜圖（含臉孔、服裝、手指、偽字與道具），再送 H3。Ref2VA 可考慮保留原 face/body，另加場景圖；先查實際節點能力與資源成本，單段驗證額外參考是否有效，不假定一定支援或改善。
4. 在 Ref2VA 六節中說清場景圖只指導環境／構圖；原 face/body 只指導同一人的外貌。若改用真正的首幀 I2VA，必須按 I2VA 語法及節點設定，不能仍宣稱原 Ref2VA 雙參考保證存在。固定雙參考是硬性需求時，先維持 Ref2VA。
5. 圖片不提供聲線保證；生成影片仍需逐段看 contact sheet、結尾幀及 CPU Whisper，另核對音色與聽感。記錄圖檔、模型／工具、prompt、參考角色、take 與結果。

## 5. 保護已收錄 take 與可恢復進度

- 選片以不可變的版本檔（例如 `seg01_t5.mp4`）為準，另存 `accepted_takes.json`：段號、take、完整路徑、畫面結果、語音結果與放寬標準。
- `seg01.mp4` 常被渲染器當作「最新產出」覆寫，**最新不等於最佳**。較晚完成的舊重抽不得取代已收錄 take；保留為未驗收備選。剪接直接引用版本檔，或在所有相關寫入完成後從選片表恢復來源並核對內容。
- QA 報告綁定實際版本／檔案身分；不得沿用另一個 take 的 pass。已有合格 take 時不再為同一失敗原因無限重抽，回到剩餘段落。
- README 保存 Rejected、選片、修補與定剪參數；重新產生劇本時不得覆蓋這些進度。全片完成後驗證槽長、尺寸、音訊、逐句轉錄及 FB SRT 對時，才標為交付。
