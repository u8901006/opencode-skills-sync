# 衛教文章章節回填

把一本書的翻譯章節（原始材料）與由它生成的衛教文章 v2 並列比對，找出文章漏掉的原章節實質內容，忠實補進文章，並維持系列管線的一致性與同步驗證。常見觸發：使用者給出兩個檔案路徑，並點名一個補充角度（如「加入標準目標規劃實做流程的方法與引導」）。

## 輸入

- 文章路徑（如 `article/07-標準目標規劃-v2.md`）
- 原章節路徑（如 `translated-zh-tw/ch07-標準目標規劃.md`）
- 使用者點名的補充角度——決定優先順序與組織主軸，但缺口盤點要完整

## 流程

### 1. 讀兩檔，建缺口清單

兩個檔案全文讀完再動筆。對照時分三類：

- **已涵蓋**：概念、案例摘要、安全提醒已在文章出現（通常在「核心觀念」「衛教說明」節）。
- **缺口**：原章節有、文章沒有的實質內容——逐步流程、引導問句原文、順序原則、措辭規則、事前準備、變體與調整方式。
- **不該搬**：對民眾有風險的操作細節（見下方「安全框架」），以及與點名角度無關、搬了會失焦的枝節。

### 2. 查系列慣例

每個管線略有差異，動筆前先確認：

- **驗證腳本**：找管線內的 verify 腳本（如 `scripts/verify_article.py`），先讀一遍記住同步規則。常見規則：FAQ markdown 與 FAQPage JSON-LD 逐字一致（含題目順序）、frontmatter description 與 Article JSON-LD 一致、keywords 順序一致。沒有腳本的管線，至少人工核對這三個同步點。
- **術語**：跟隨 v2 文章自己的定稿術語（例如文章用「誘發情境」而原章節譯「觸發源」），首次出現用括號橋接（「誘發情境（書中稱觸發源）」）。系列共通概念可比照其他文章的用法（如負向信念＝負向認知）。
- **文體**：正文純散文；粗體只用於警告等真正需要強調處，不當步驟標籤；破折號只留有實際功能者。口吻對民眾說話，平實。
- **參考文獻**：只加正文實際引用到的文獻，沿用文章現有格式；原書引用有明顯筆誤時可查證後修正（如頁碼 465-1487 實為 1465–1487），不確定就照原書。

### 3. 寫入補充

- **位置**：新增 `##` 節放在概念說明之後、自助練習之前（典型節序：核心觀念→衛教說明→**補充的實做內容**→自我覺察→求助→FAQ），或依該系列既有節序插入。
- **忠實度**：引導問句逐字引用原譯文；案例用原書化名並標明去識別化；引註（作者, 年份）照原章節保留。不改變原章節的主張、順序、條件與歸因。
- **去重**：前面節若已摘要過同一案例，改寫成一句引入（如「作者便以她為例，見下一節」），細節留給新節。
- **FAQ**：為新內容增題，每題對應一個具體疑問，按文章流程順序插入；答案二至四句。
- **description**：frontmatter description 改寫以涵蓋新內容——改完必須逐字同步到 Article JSON-LD。

### 4. 同步 JSON-LD

三個同步點，全部逐字、含順序：

1. frontmatter description ↔ Article JSON-LD `description`
2. FAQ markdown（`## 常見問題 FAQ` 內每個 `###` 問句與答案）↔ FAQPage `mainEntity` 的 `name` 與 `text`
3. frontmatter keywords ↔ Article JSON-LD `keywords`

歷史教訓：FAQ 手改後 JSON-LD 最常漏同步。任一側改字，同次改另一側。

### 5. 驗證

跑管線驗證腳本，必須 PASS：

```
py -3 scripts/verify_article.py "article/07-標準目標規劃-v2.md"
```

FAIL 時按訊息修同步，不繞過腳本。沒有驗證腳本的管線，以人工核對代替並明確告知使用者。

### 6. 去AI語氣

對本次新寫的內容載入 humanizer-zh-tw 施作；既有未動的段落不強改。新寫內容常見的毛病：

- 粗體步驟標籤（`**步驟一：…**`）→「第一步，…」自然散文推進
- 破折號連發 → 冒號或拆句
- 「不是X，而是Y」空泛假對比 → 直接陳述（否定部分糾正真實誤解時可保留）
- 同段重複「書中」「案主」等詞 → 收斂
- 層疊修飾（「行為、情緒、想法或身體感覺性質相近的過去經驗」）→ 拆短或改問句

保護區：frontmatter 與 JSON-LD 屬資料不動——但 FAQ markdown 若在這步改字，FAQPage JSON-LD 要同步再改一次。

完成後重掃殘留並重跑 verify：

```
grep -n "——\|\*\*" 文章路徑   # 正文應無殘留
```

掃出的破折號先分辨再動手：引導問句等逐字引文內的破折號照引文保留；既有段落（本次未改）裡承擔插入說明功能的成對破折號也不算殘留。只清本次新寫內容裡拿破折號當萬用連接的用法。

## 安全框架（衛教文章鐵則）

治療技術的流程與引導問句，一律寫成「治療室裡會發生什麼、治療師會怎麼問」，明確標示由治療師評估後使用、不是自行操作腳本。文章開頭的安全提醒、「不提供自行搜尋或喚起記憶的方法」等既有立場，不能因為補充內容而弱化；有風險的回溯類技術須照原書附上穩定化準備與知情同意的說明。

## 交付

向使用者報告：缺口清單（補了什麼、刻意不搬什麼）、新節位置與組織方式、FAQ／description／參考文獻的連動修改、verify 結果、去AI修改要點。
