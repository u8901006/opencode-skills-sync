# SEO 文章檢核 (SEO Article Checker)

對一篇 SEO 導向文章執行十項標準審核，並輸出**可直接套用**的修改建議——不是空泛評語，而是「這一段應改成這樣」。

## 啟動方式

收到要檢核的文章後，先完成以下動作再進入逐項檢查：

1. **讀完整篇**（含 YAML frontmatter）。長文必須讀完，不可只抽樣。
2. **辨識主關鍵字與次關鍵字**：從 frontmatter `keywords`、標題、首段、URL slug 中萃取。若使用者未指定，從文章中推測並在報告開頭列出讓使用者確認。
3. **辨識搜尋意圖類型**：資訊型（Informational）／導航型／交易型／商業調查型。多數知識文屬資訊型。
4. **辨識品牌**：從 frontmatter `author`、`site`、文末 CTA 推測；無則詢問。

完成上述後，逐項檢核以下十點，每項都用「✅ 通過 / ⚠️ 部分通過 / ❌ 未通過」標示，並附**具體事證**（引用原文行號或片段）與**修改建議**（給出可貼上的重寫文字）。

## 十項檢核標準

### 1. 符合搜尋意圖 (Search Intent Match)

- 文章類型是否對應主關鍵字背後的意圖？例如「EMDR 是什麼」屬資訊型，不該堆滿購買 CTA；「最佳 EMDR 治療師推薦」屬商業調查，應有比較表。
- **首段三句內**是否直接回答主關鍵字？Google 偏好「答案優先」結構。
- 是否覆蓋使用者隱含的後續問題（People Also Ask 類型）？

判定不通過時，給出「應補充哪個段落／應刪減哪個離題段落」。

### 2. 完全比對關鍵字置入 (Exact-Match Keyword Placement)

主關鍵字必須以**完全比對形式**（不可拆字、不可同義替換）出現於：

- [ ] `<title>`（H1 標題）
- [ ] meta description（frontmatter `description`）
- [ ] URL slug
- [ ] 首段第一或第二句
- [ ] 至少一個 H2
- [ ] 結尾段
- [ ] 圖片 alt text（至少一張）

關鍵字密度建議落在 **0.8%–2.5%**，過低=信號不足、過高=堆砌懲罰。請實際估算（出現次數 / 總字數），列出數字。

次關鍵字、長尾變體可使用同義／語意相關詞，無需完全比對。

### 3. 大標小標設定 (Heading Hierarchy)

- 全文僅一個 H1，且 H1 = 文章標題（不可在 body 中再用 H1）。
- H2 數量 3–8 個為佳；每個 H2 處理一個獨立子題。
- H3 用於 H2 下的分項；不可跳階（不可從 H2 直接跳 H4）。
- 標題本身要能獨立看懂——讀者掃 H2 就能掌握文章骨架。
- 至少 30%–50% 的 H2 / H3 含關鍵字或語意相關詞，但避免每個標題都硬塞主關鍵字。

判定時請輸出目前的 heading outline（樹狀），標示問題節點。

### 4. 相關內部連結 (Internal Links)

- 篇幅 1500 字以上至少 **3 個內部連結**；3000 字以上至少 5 個。
- 連結錨點（anchor text）使用**描述性語句**，非「點此」「這裡」。
- 連往的頁面必須與當前主題語意相關（同一個 topic cluster）。
- 不可全部指向首頁或同一頁。

若使用者提供站點結構或索引檔，請從中挑選真實可用的 URL；若無，**列出該補連結的位置與建議錨點文字**，並標註「需確認目標 URL」。

### 5. 可信外部連結 (Credible External Links)

- 至少 **2–4 個權威外部連結**：政府機構（.gov、CDC、衛福部）、學術期刊（DOI 可解析）、知名研究機構（WHO、APA、NIH、Cochrane）、官方標準文件。
- **禁止連向**：競爭對手商業頁、低權威內容農場、無 DOI 的可疑研究、過期超過 10 年的統計（除非歷史脈絡）。
- 所有引用統計必須能追溯到一手來源；二手摘要不算。
- DOI 必須可解析（doi.org/xxx 能打開）。標註任何「需驗證」的引用。

外部連結建議使用 `rel="noopener"`；若是付費／合作關係連結需加 `rel="sponsored"`。

### 6. 配圖 1–3 張 (Images)

- 至少 **1 張、不超過 3 張**主要視覺（資訊圖、流程圖、示意圖、實拍）。純裝飾的 stock photo 不算。
- 每張圖須有：
  - **alt text**：描述圖片內容 + 自然帶入關鍵字（不可堆砌）
  - **caption**（圖說）：補充圖片無法傳達的脈絡
  - **檔名語意化**：`emdr-eight-phases.png` 而非 `image001.png`
- 圖片格式建議 WebP / AVIF；尺寸壓縮至 200KB 以內。
- 首屏圖建議標 `loading="eager"`，其餘 `loading="lazy"`。

若文章缺圖，**指定該插哪幾張、放哪段之後、建議圖片內容**。

### 7. FAQ 與長尾關鍵字 (FAQ & Long-tail Keywords)

- 文末或側欄需有 **FAQ 區塊**，3–6 題為佳。
- 每題標題本身即是一個長尾關鍵字（例如「EMDR 治療有副作用嗎？」「EMDR 一次療程要多久？」）。
- 回答精簡 2–4 句，可獨立成 featured snippet。
- 標記 `FAQPage` schema（JSON-LD）——若文章是 .md，請在 frontmatter 或文末給出可貼上的 schema 片段。
- 同時檢查正文是否自然涵蓋 People Also Ask 級長尾詞；若缺，列出 3–5 個建議補入的長尾詞。

### 8. 品牌置入訊息 (Brand Placement)

- 品牌名稱在以下位置至少各出現一次：首段（自然帶入）、中段一處、結尾 CTA。
- 不可變成廣告——資訊型文章中品牌應作為「資訊提供者 / 服務示範」出現，而非反覆推銷。
- 結尾 CTA 必須與文章主題語意連貫（談 EMDR 治療→可導向預約 / 諮詢；不可硬導不相關產品）。
- 品牌故事或差異化訊息（USP）至少出現一次，最好是讀者已被內容說服後的位置（文章 70%–90% 處）。
- 若文章完全缺品牌，**指出三個應置入點與建議寫法**。

### 9. 錯字與語病檢查 (Typo & Grammar)

- 逐段檢查中文錯別字（同音異字最常見：「在／再」、「的／得／地」、「以／已」）。
- 標點：中文用全形（，。「」），英文用半形；中英混排數字前後留半形空格。
- 專有名詞拼寫一致：EMDR 不寫成 emdr / E.M.D.R.；品牌、人名、機構名整篇一致。
- 數字與單位：阿拉伯數字配半形（30 分鐘）；單位前留空格。
- 連續重複詞、漏字、贅字。

**輸出格式**：列出「行號／原文 → 修正」對照表；錯字 5 處以上請另開列表，不要混在主報告中。

### 10. 資訊查核 (Fact Check)

每一個**事實性宣稱**都必須能對應到來源：

- 統計數字 → 來源 + 年份（用最新可得年份；CDC/WHO 通常每年更新）。
- 研究結論 → 第一作者 + 年份 + DOI；DOI 須可解析。
- 醫療／心理／法律建議 → 官方指引或同儕審查文獻，不可只引用部落格。
- 引用須區分「強證據（系統回顧、RCT、官方指引）」與「弱證據（個案、專家意見、新聞稿）」。

無法驗證的宣稱請標 **`(需驗證)`** 並列入報告末「待查核清單」，不可靜默通過。

- 次關鍵字：<>

- 文章字數：<>
- 預估閱讀時間：<> 分鐘
- 品牌：<>

## 十項檢核總覽

|---|-----|------|

## 逐項細節

**事證：** 首段第三句才出現關鍵字，前兩句談歷史背景。

## 工作原則

- **誠實標示無法驗證項目**。DOI 解析、外部連結存活、最新統計年份等若沒有工具可即時查證，標 `(需驗證)`，不要假裝驗證過。WebFetch / WebSearch 可用時優先驗證 DOI 與權威來源。
- **不要重寫整篇文章**——除非使用者明確要求。檢核 skill 的本職是「指出問題 + 給該段重寫範例」。要全文重寫，使用者會呼叫 `copywriting-optimizer` 或其他改寫 skill。
- **保留 YAML frontmatter**。任何建議若涉及 frontmatter（description / keywords / schema），明確標示要改 frontmatter 的哪個欄位。
- **不要新增空泛建議**。「建議多放關鍵字」是空話；「在 H2『EMDR 八階段』後第二段補入主關鍵字 EMDR 治療」才有用。
- **語言對齊**：使用者用繁體中文寫作時，全程繁體中文輸出；簡體則簡體；英文則英文。
- **長文檢核可耗時，但不可偷懶**。逐項都要有事證，不可只在某幾項給結論就跳過。

## 何時建議呼叫其他 skill

- 文案說服力／節奏／釣鉤明顯不足 → 建議使用者另跑 `copywriting-optimizer`。
- AI 痕跡明顯（破折號滿天飛、三段式結構、空洞排比） → 建議跑 `humanizer-zh-tw`。
- 引用大量學術文獻、需驗證真實性 → 建議跑 `deep-research` 的 fact-check 模式。
- 文章本身結構需重寫，不只是檢核 → 建議跑 `seo-writing-skill`。

檢核 skill 的角色是「品管站」，不是「重寫站」。
